# CP6 — Frontend: Search & Browse

## Goal

Complete the technical specification's CP6 checkpoint: a logged-in user can view another student's card by searching their exact login, and can discover students by browsing campus → coalition → participant list. Both paths resolve to a rendered read-only card backed by live School21 data from `GET /api/participants/:login`.

**Done when (spec):** searching a known login and browsing via campus/coalition both resolve to a rendered card.

## Current State

- Backend is complete for CP6 (CP3): all four endpoints sit behind `SessionGuard` and already return typed `shared-types` contracts:
  - `GET /api/participants/:login` → `ParticipantSearchResponse` (= `CardProfile`, live proxy, includes `domainRank` from CP4; 404 → `Participant 'x' was not found`)
  - `GET /api/campuses` → `CampusListResponse` (`{ campuses: [{ id, shortName, fullName }] }`)
  - `GET /api/campuses/:campusId/coalitions` → `CoalitionListResponse` (`{ coalitions: [{ coalitionId, name }] }`)
  - `GET /api/coalitions/:coalitionId/participants` → `ParticipantLoginsResponse` (`{ participants: string[] }` — logins only)
- Frontend (`apps/web`, Next 16 App Router, client components + fetch, CSS Modules, dark-fantasy tokens):
  - `/login`, `/card` (own cached card with CardShell tabs), `src/proxy.ts` presence-only cookie gate currently matching only `/card/:path*`
  - `src/lib/api.ts` has `request<T>`, `ApiError` (`isUnauthorized`, `isNotSynced`), `getOwnCard`, `login`
  - `CardShell` renders header (login, class/parallel, Domain + Rank line, level + tier), stale banner, Overview/Stats/Achievements tabs
- No global navigation exists; `/card` is the only authenticated page.
- Frontend validation convention (settled): build + lint + live checks with a locally minted dev session cookie; no frontend test stack.

## Settled Decisions

- **Browse structure: nested routes** — `/browse` (campuses), `/browse/[campusId]` (coalitions), `/browse/[campusId]/[coalitionId]` (participant logins). Deep-linkable and back-button native via App Router dynamic segments.
- **Guest card: reuse CardShell** — generalize its prop type from `CardResponse` to `CardProfile & { stale?: boolean; lastSyncedAt?: string }` (CardResponse stays assignable). A `guest` variant renders a compact informational banner; all three panels and the Domain + Rank line are reused unchanged.
- **Navigation: top nav on all authenticated pages** — `My Card` / `Browse` links plus an exact-login search input that navigates to `/participant/[login]`. Implemented via an `(authed)` route group layout so `/login` and `/` stay nav-free; route groups do not change URLs.
- **Search is exact-match only** (no typeahead, no debounce, no client-side login validation beyond trimming) — mirrors the spec's "no public directory of logins; search works by exact login only."
- **Data-honesty unchanged**: guest cards show only real API fields; the live guest card legitimately shows `domainRank` (CP4) and no stale banner (live endpoint has no `stale`/`lastSyncedAt`).
- **No backend changes.** If a screen seems to need a new field or endpoint, stop and flag — that is a CP3 revision, not a CP6 task.
- Keep the no-test-stack decision: validation is builds, lint, curl route checks, and static render checks against the real API payloads.

## Out of Scope

- Logout (no API endpoint exists)
- Badge icon proxying (host returns the SPA HTML shell; documented in CP4/CP5 — revisit in CP7+ with an authenticated asset path)
- Pagination/virtualization for large coalition participant lists (plain list in CP6; note as follow-up)
- Participant card caching or recent-searches persistence
- CP7 polish (full error/empty-state visual pass, dark-fantasy deep pass)

## Implementation Tasks

### 1. API client extensions — `apps/web/src/lib/api.ts`

Add typed functions reusing the existing `request<T>` / `ApiError` machinery:

- `searchParticipant(login: string): Promise<ParticipantSearchResponse>` → `GET /api/participants/${encodeURIComponent(login)}`
- `getCampuses(): Promise<CampusListResponse>` → `GET /api/campuses`
- `getCampusCoalitions(campusId: string): Promise<CoalitionListResponse>` → `GET /api/campuses/${encodeURIComponent(campusId)}/coalitions`
- `getCoalitionParticipants(coalitionId: string): Promise<ParticipantLoginsResponse>` → `GET /api/coalitions/${encodeURIComponent(coalitionId)}/participants`

Import all response types with `import type`. Do not add new error classes; callers branch on `ApiError.status` (`401` → redirect to `/login`, `404` on participant → not-found state, others → retry state).

### 2. Shared fetch hook — `apps/web/src/lib/useResource.ts` (new)

Extract the pattern already used by `/card` into a small reusable client hook:

```ts
useResource<T>(fetcher: () => Promise<T>, deps: unknown[]):
  { data: T | null; error: ApiError | null; loading: boolean; reload: () => void }
```

- Cancellation-safe (`cancelled` flag, like the current card page effect) to satisfy `react-hooks/set-state-in-effect` lint
- `401` handling stays in pages (they own `router.replace('/login')`) — the hook surfaces the error
- Used by the participant page and all three browse pages; the own-card page may keep its current inline logic or adopt the hook (prefer adopting to remove duplication)

### 3. Cookie gate — `apps/web/src/proxy.ts`

Extend `config.matcher` to an array covering every authenticated route:

```ts
matcher: ["/card/:path*", "/browse/:path*", "/participant/:path*"]
```

Presence-only check unchanged; `SessionGuard` remains the source of truth.

### 4. Route group + navigation shell

- Create `apps/web/src/app/(authed)/layout.tsx` — server component rendering `<AppNav />` above `{children}`.
- Move `apps/web/src/app/card/` (page + module css) → `apps/web/src/app/(authed)/card/`. URLs unchanged.
- Create `apps/web/src/components/AppNav.tsx` (+ module css), client component:
  - `<nav aria-label="Primary">` with brand text `S21 Stat Card`
  - `My Card` → `/card`, `Browse` → `/browse` (active state via `usePathname`)
  - search form: `<form onSubmit>` → trimmed login; empty → no-op; otherwise `router.push(\`/participant/${encodeURIComponent(login)}\`)`
  - input with `aria-label="Search by exact login"`, `autoComplete="off"`, `enterKeyHint="search"`; submit button with pending-safe disabled state while navigating (optional)
  - styling: existing tokens, `clip-small` on the submit button, angled corners per design system; compact single strip, wraps safely on mobile

### 5. CardShell generalization + guest variant — `apps/web/src/components/CardShell.tsx` (+ css)

- Change the prop type to `CardProfile & { stale?: boolean; lastSyncedAt?: string }`; `data.stale` guard already renders nothing when the field is absent.
- Add optional `guest?: boolean` prop:
  - when set, render a slim banner above the header: `LIVE SCHOOL21 DATA · READ-ONLY` (distinct from the own-card stale banner; gold accent, no fabricated freshness claim)
  - everything else — login, class/parallel, Domain // Rank line (`Unclassified` on nulls), level + tier frame, tabs — renders identically from the live `CardProfile`
- No other component changes; `OverviewPanel`/`StatsPanel`/`AchievementsPanel` consume `CardProfile` fields they already handle (nullable points/feedback, duplicate-safe keys).

### 6. Campus list page — `apps/web/src/app/(authed)/browse/page.tsx`

Client page using `useResource(getCampuses, [])`:

- loading → skeleton strip; error → message + retry; `401` → `router.replace('/login')`
- success → heading `Browse` + grid of campus tiles (`clip-small`): `shortName` prominent, `fullName` secondary; each links to `/browse/[campusId]`
- empty state: `No campuses available.`

### 7. Coalition list page — `apps/web/src/app/(authed)/browse/[campusId]/page.tsx`

Client page; `campusId` from `useParams()`:

- fetch campuses and coalitions **in parallel** (`Promise.all` with two `useResource` calls, or one combined fetcher) — campuses provide the breadcrumb name so deep links work without prior state
- breadcrumb: `Browse / {campus.shortName}` (link back to `/browse`); unknown campusId (not in list) → render breadcrumb with the raw id and still show coalitions for that id
- coalition tiles: `name` prominent; link to `/browse/[campusId]/[coalitionId]`
- loading/error/401/empty states as above; empty: `No coalitions for this campus.`

### 8. Participant list page — `apps/web/src/app/(authed)/browse/[campusId]/[coalitionId]/page.tsx`

Client page; both params from `useParams()`:

- fetch coalitions (breadcrumb name; same deep-link rationale) and participants in parallel
- breadcrumb: `Browse / {campus-shortName-or-id} / {coalition.name}`, each segment linked to its level (campus name needs campuses too — fetch all three lists in parallel; they are small)
- participants rendered as a clickable grid/list of logins (`clip-small` tiles) → `/participant/[login]`
- empty: `No participants in this coalition.`; loading/error/401 as above
- shared stylesheet `browse.module.css` for all three browse pages to avoid triple duplication

### 9. Participant read-only card — `apps/web/src/app/(authed)/participant/[login]/page.tsx`

Client page; `login` from `useParams()` (effect deps include `login` so searching a different login from the same page refetches):

- `useResource(() => searchParticipant(login), [login])`
- loading → skeleton with copy that sets expectations (`Summoning card from School21...` — this endpoint makes 7 sequential upstream calls and takes seconds)
- `401` → redirect `/login`; `404` → friendly not-found state using the API message (`No student with login '{login}' was found.`) + back-to-browse link; other errors → retry
- success → `<CardShell data={profile} guest />`
- document (page copy not required): searching your own login shows your **live** card — data-honest, differs from the cached own card by design

## Acceptance Criteria

- Nav search for a known login lands on `/participant/[login]` and renders the read-only live card, field-by-field equal to `curl GET /api/participants/:login` for the same session.
- Browsing `/browse` → campus → coalition → participant list → click renders the same read-only card (spec's done-when).
- All authenticated routes redirect to `/login` without a cookie and reject forged cookies with 401 from the API.
- Domain + Rank (or `Unclassified`) renders on guest cards, separate from official level.
- Empty, loading, not-found, and retry states exist on every new screen; keyboard navigation and labels are intact.
- API tests remain 68/68; web build + lint clean; no backend or shared-types source changes.

## Risks and Follow-ups

- **Live proxy latency**: the participant endpoint performs 7 sequential School21 calls; the skeleton copy must set expectations. If it proves unusable, a backend concurrency change is a CP3 revision — flag, don't hack around it client-side.
- **Large participant lists**: coalitions can be big; plain rendering first, pagination as a follow-up if real data shows a problem.
- **Breadcrumb refetching** costs 1–2 extra small GETs per browse page for deep-link robustness; acceptable trade-off, revisit if the school API rate-limits.
- **Rate limiting**: rapid clicking through many live cards triggers upstream calls per card; acceptable for CP6, but do not add prefetching/typeahead (would multiply requests).
- School21 logins are ASCII-safe, but still `encodeURIComponent` every interpolated path segment defensively.
- Route group `(authed)` must not wrap `/login` or `/` — moving those would break the unauthenticated flows.
